# 統計学の基礎（図解ドリル）

**先に `question-authoring`（共通ルール・適用手順）と `explanation-clarity`（わかりやすさの方法論）を読むこと。** ここは本ドリル固有の情報だけ。

## この問題集の性格（他の区分と根本的に違う）

資格試験対策ではなく**教養ドリル**。ユウが読んでいる統計教科書（363ページ）の用語を、前提知識ゼロで腹落ちさせるのが目的。

- **問題は入口、解説が主役。** 問題は暗記チェックではなく、解説を読ませるためのフック。お小遣い・靴屋・アイスの売上のような身近な場面から入る
- **解説は小学生でも分かるレベルに振り切る**（ユウ確認済み 2026-07-29）。ただし漢字は普通に使う。読者は大人
- **全問に `viz`（1枚の図解SVG）を付ける。** これがこのドリルの看板。図なしの問題を足さない

## 大量生産の実績（2026-07-30）

セット2〜8（76問）は **Workflow オーケストレーション**で作った: Sonnet 作問7並列（各自スキル3枚＋Set1雛形を読み、SVGをPNG化して目視検証まで）、別 Sonnet がセットごとに監査（事実誤り最優先）、指摘があったセットのみ Sonnet が修正。PM（メインループ）は用語リストの発注・検収・DB適用・コミットのみ。21エージェント・約24分・レビュー指摘17件全修正。同じ規模の増産はこの型を再利用する（スクリプトは workflows/scripts/ に残る）。

- セット内の並びは**「前の用語が次の用語の前提になる」依存順**（例: 分散、その次に標準偏差、その次に偏差値）
- マニアックな検定名（ブルーシュ・ペーガン検定等）は土台の8セットが済むまで足さない

## source_ref

`stats<セット番号>-q<NN>`（ゼロ埋め2桁）。例: `stats1-q01`、セット2なら `stats2-q01`。

## 問題の形

- 4択 single。問題文は1〜3文の**身近なシナリオ**（クラスのテスト・お小遣い・靴屋の仕入れ・アイスの売上）
- 誤答は「隣の概念」を置く（平均を問うなら中央値・最頻値の値、第3四分位数を問うなら第1四分位数）。共通ルールの長さ縛り（正解を単独最長にしない）を厳守
- `code` 列と `snippet` は基本使わない。数式を見せたいときも `think` の文中で言葉に開く

## 解説の流儀（ユウの要望4点に全キーを対応させる）

| 要望 | キー |
|---|---|
| 何がどういう意味か | `asked` + `kid`（ざっくり言うと） |
| たとえで直感 | `eg`（一番力を入れる。やじろべえ・両替・記念写真の真ん中の人、のレベル） |
| なんのためにあるか | `why_asked`（「この概念が無いと何に困るか・なぜ発明されたか」を書く） |
| どういうことに役立つか | `usecase`（実生活・仕事の場面） |

加えて `point`（決め手1文）・`terms`（2〜4個）・`think`（因果の背骨。「なぜ2乗するのか」「なぜ外れ値に強いのか」を鎖でつなぐ）・`vs`（平均vs中央値、外れ値vs偏差値のような隣接概念）・`opt`（選択肢と同数）・**`viz`**。

## viz（図解SVG）の書き方

`explanation_data.viz` にインラインSVG文字列。描画は `RichExplanation`（`src/features/quiz/components/rich-explanation.tsx`）の「図で見る」セクション（`eg` の直後）。型は `ExplanationData.viz`（`src/features/quiz/lib/types.ts`）。

- `viewBox="0 0 340 150"` 前後（高さは内容に合わせ 120〜150）。幅340pxに収まらない文字は必ず見切れる
- 配色（静かな計器・ダーク。背景は描画側が `#141720` を敷くので塗らない）:
  - 文字 muted `#8892a4` / 強調 `#e8eaf0` / アクセント `#3b82f6`・`#60a5fa`
  - 罫線 `#2a2f3f` / 緑（正しい・OK） `#6ab08d` / 赤（外れ値・注意） `#c47070` / 琥珀（対比） `#c9a04a`
- font-size 9〜13。1枚に伝えることは1つ。目盛り・凡例を盛らない
- 定番の型: 数直線＋点＋支点（平均）、点列＋真ん中強調（中央値）、棒の高さ（最頻値・ヒストグラム）、帯の4等分（四分位）、箱ひげ、ベル曲線＋マーカー（偏差値・z値）、散布図＋破線トレンド、2×2マス（混同行列・検定の過誤）

### 制作と検証の手順（Set 1 で確立）

1. **Python 生成スクリプト**で問題 dict＋SVG から SQL を生成する（`explanation-clarity` の流儀。手書きSQLはエスケープ事故のもと）。スクリプト内で位置参照の正規表現チェックと「正解が単独最長でないか」を自動チェックする
2. **SVG は必ずPNG化して目視する。** 文字の重なり・見切れはコードだけでは気づけない（Set 1 では12枚中4枚に重なりがあった）:
   ```bash
   qlmanage -t -s 680 -o . viz01.svg   # macOS標準。ダーク背景を style で敷いてから
   ```
3. 適用・件数検証は共通ルールどおり。`viz` の充足も数える:
   ```sql
   select count(*) filter (where explanation_data ? 'viz') from ...;
   ```

## 内容の注意

- 数値例は**その場で検算できる小さい数**にする（5人の点数、310÷5=62 のように読者が暗算で追える規模）
- 「相関＝因果ではない」「偏差値は割合ではない」のような**世間で誤解されがちな点**を `vs` で必ず拾う
- 教科書の索引にある用語でも、依存する前提（例: 正規分布を知らないと偏差値の16%が出せない）があるときは、先行セットで前提を張ってから出す。先に出すなら「分布が正規分布に近ければ」のような留保を付けて接地する
