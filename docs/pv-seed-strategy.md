## 3. チャンク台帳（唯一の整合性管理）

`docs/pv-chunk-ledger.md` を投入開始前（9/1）に作る。**全200チャンクの正本**で、以下を1行1チャンクで持つ:

```
| chunk | クラスタ | tier | 初出セット | 再登場セット | 使用場面(短) | レジスター | 由来(harvest/生成) |
```

台帳が守るもの:
1. **重複防止** — 同じチャンクを別セットでうっかり新出させない
2. **再登場ルール** — 再登場は「場面・レジスター・トラップ全変え」のときだけ。台帳の初出行を見て差分を確認してから書く
3. **クラスタ内相互誤答** — 誤答肢に使う近縁語をクラスタ列から引く
4. **カバレッジ** — 各クラスタ 4〜6 チャンクを下限に。偏りは台帳で一目

ハーベスト素材（〜8/30 収集分）は 9/1 の台帳作成時にクラスタへ振り分け、`由来=harvest` を付ける。**harvest 由来を優先して問題化する**（実文は場面がリアルで直訳トラップが作りやすい）。振り分け先のないハーベスト文は捨てずに台帳末尾の「未分類」に置く。

## 4. 1セットの投入手順（毎回同じ・所要1セッション）

1. **スキルを読む**: `question-authoring-pv` ＋共通 `question-authoring`
2. **台帳から今回の25チャンクを確定**（クラスタ配分・再登場枠を先に決める）
3. **作問**（1問ずつ）: 場面＋レジスタータグ → **誤答3種を先に書く**（直訳／粒子ニアミス／レジスターミス、クラスタ内近縁語を1つ以上）→ 正解文を最後に → explanation_data（`vs`=トラップ解剖が主役）
4. **SQL 作成**: `supabase/migrations/000NN_seed_pv-<set>.sql`（次番号は 00045〜）。subjects/categories の INSERT は各セット初回のみ
5. **検証ゲート（§5）を全通過**
6. **`db.sh apply`** → 件数確認 → 本番 UI で 2〜3 問実走（Speak-First 表示・解説描画）
7. **台帳を更新**（初出/再登場セット欄を埋める）→ SQL と台帳をコミット

## 5. 検証ゲート（apply 前後の必須チェック）

| # | チェック | 方法 |
|---|---|---|
| 1 | 件数・opt 充足 | 共通スキルの count クエリ（total = with_opt = 期待数） |
| 2 | 長さリーク | 共通スキルの clen > dmax クエリで 0 件 |
| 3 | 位置参照（A/B/C/D） | 解説自由文に位置参照なし（シャッフル停止を防ぐ） |
| 4 | multi の correct_indices | pv スキル末尾のクエリで NULL 0 件 |
| 5 | カテゴリ名完全一致 | 期待件数と INSERT 結果が一致（不一致は黙って落ちる） |
| 6 | トラップ3種の実装 | 目視: 各問の誤答が ①直訳 ②粒子 ③レジスターに対応しているか |
| 7 | 台帳整合 | 新出チャンクが台帳にあり、再登場が差分条件を満たすか |

1〜5 は SQL で機械的に。6〜7 は目視（各セット25問なら現実的）。
