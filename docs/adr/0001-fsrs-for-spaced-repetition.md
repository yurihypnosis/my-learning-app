# 0001: 間隔反復エンジンに FSRS-4.5 を自前実装で採用

- Status: Accepted
- Date: 2026-06（migration 00018 で導入）

## Context

初期の出題制御は手書きのルールだった（「3回連続正解なら2週間出さない」「正解かつ理解度
『完璧』なら1週間出さない」）。シンプルだが問題が2つあった。

1. 間隔が固定で、問題ごとの覚えやすさ・忘れやすさを反映できない
2. 「今この問題をどれくらい覚えているか」という連続値が得られないため、
   合格確率の推定（ADR 0002）の材料にならない

単語カード機能（293語）の追加で、本格的な間隔反復が必須になった。

## Decision

FSRS-4.5（Free Spaced Repetition Scheduler）を `src/lib/quiz/fsrs.ts` に**自前実装**する。

- カードを安定度 S（日）と難易度 D（1..10）でモデル化し、経過日数から保持率 R を計算。
  R が目標保持率（0.9）に落ちる日を次の復習日とする
- 重みは open-spaced-repetition 公開のデフォルト17個を使用（ユーザー最適化は将来課題。
  そのために `answer_events` テーブルに生ログを蓄積している）
- アプリ独自の「確信度」入力を FSRS の grade に写像する:
  誤答→Again / 正答×勘→Hard / 正答×迷った→Good / 正答×確信→Easy。
  自己申告 grade を追加で聞く必要がなく、既存 UI がそのまま使える
- 全関数を純粋関数にし、`now` は必ず引数で渡す（時計依存を排除しテスト可能に）

### 採用しなかった選択肢

- **ts-fsrs 等の既存ライブラリ**: アルゴリズム自体が学習対象として価値があること、
  依存を最小に保つ方針、確信度→grade 写像などの改造が必要だったことから自前実装を選んだ。
  実装は約170行で、公開テストベクタと突き合わせ可能な規模
- **SM-2（Anki 旧方式）**: 保持率 R という連続値が出ない。R は ADR 0002 の合格確率
  モデルの入力なので、R を第一級で扱う FSRS が必須だった

## Consequences

- 良: 問題ごとに最適化された復習間隔。「現在の保持率」が読み出せるため、
  弱点抽出・合格ナビ・合格確率がすべてこの1つのモデルの上に載った
- 良: 純粋関数群なのでテストが書きやすい（fsrs.test.ts）
- 悪: FSRS 導入前の進捗には FSRS 状態がない。`retentionEstimate()` は
  FSRS 状態があれば R、なければ従来 mastery、未着手は 0 とフォールバックする
  二層構造になっており、この互換層は当面残る
- 悪: 重み最適化は未実装。デフォルト重みは英単語カード由来なので、
  技術試験の4択問題に対しては保守的な可能性がある
