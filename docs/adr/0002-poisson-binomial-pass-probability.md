# 0002: 合格確率はポアソン二項分布で厳密計算（ML 不使用）

- Status: Accepted
- Date: 2026-07（readiness.ts）

## Context

「本試験を今日受けたら受かるのか」を1つの数字で出したい。よくある実装は
正答率の移動平均や、学習データを使った ML 予測だが、このアプリは
ユーザー1人・データ量も少なく、根拠を説明できない数字は欲しくなかった。

## Decision

合格確率を**問題単位の正答確率の合成**として、ポアソン二項分布で厳密に計算する
（`src/lib/quiz/readiness.ts`）。

1. **1問の正答確率** = `R + (1-R) × g`。思い出せれば正答、思い出せなくても
   選択肢から当たる（R=FSRS の想起確率、g=1/選択肢数）
2. **実力の推定**は直近の「正誤 × 確信度」から。勘で当てた正解は推測床付近まで
   しか評価しない（アプリの思想「まぐれ当たりは加算しない」を確率に反映）。
   実力 × 現在の想起 R をかけ、推測床でクランプしたものがその問題の正答確率
3. **未着手の問題**は「その分野の着手済み問題の平均能力」をベイズ縮約
   （事前分布=推測当たり、擬似観測数3）して予測する。未着手分野は推測当たりまで落ちる
4. 全問の正答確率を並べ、**ポアソン二項分布の PMF を動的計画法 O(n²) で厳密に**求め、
   P(正答数 ≥ 合格ライン × 問題数) を合格確率とする

合格ラインは試験ごとの公表値（GCP≈70%、CTAL-TA≈65%、DCA≈66%、未知は 72%）。

### 採用しなかった選択肢

- **ML モデル**: 学習データがユーザー1人分しかなく過学習必至。何より
  「なぜこの数字か」を説明できない。全ステップが確率論で説明できる現方式は
  数字への信頼＝学習の動機に直結する
- **正規近似（中心極限定理）**: 問題数が少ないセットで裾の精度が落ちる。
  n≤数百なら O(n²) の DP で厳密解が数 ms で出るため、近似する理由がない
- **単純な正答率平均**: 「平均70%」と「合格確率」は別物。同じ期待得点でも
  分散次第で合格確率は大きく変わり、それを表現できるのが分布計算の価値

## Consequences

- 良: すべての数字に確率論的な説明がつく。テストも決定的に書ける（readiness.test.ts）
- 良: FSRS（ADR 0001）の R をそのまま入力にでき、モデルが1本につながっている
- 悪: 「問題間の独立」を仮定している。実際は同分野の問題は相関するので、
  合格確率はやや過信気味（分散を過小評価）になる。既知の限界として受容
- 悪: 本試験の問題プールとアプリの問題プールは同一ではない。未着手汎化で
  緩和しているが、あくまで「このアプリの問題での合格確率」である
